CONTACT ENQUIRY PERMISSION_DENIED FIX
-------------------------------------
The contact form writes these exact keys to /contactEnquiries:
  name, email, phone, subject, subjectKey, message,
  status, emailStatus, createdAt, updatedAt
(and optional emailSentAt).

The admin dashboard reads the same keys and uses lowercase statuses:
  new, reviewed, resolved

IMPORTANT:
The rules shown in the earlier Firebase screenshot required a DIFFERENT
schema: customerName, customerEmail, customerPhone and capitalized statuses
such as New / Reviewed / Resolved. That mismatch is why Firebase returned
PERMISSION_DENIED even though the contactEnquiries section existed.

To fix it:
1. Firebase Console -> Realtime Database -> Rules.
2. Back up/copy your currently published rules.
3. Open FIREBASE_DATABASE_RULES.json from this ZIP.
4. Publish that complete rules document to the SAME Realtime Database
   whose URL appears in firebase.js.
5. Verify that the contactEnquiries rules use name/email/phone and lowercase
   status values. Do not combine the old customerName schema with this code.

The rules file preserves existing booking/admin/content rules and allows
unauthenticated visitors to CREATE a new contact enquiry only. Only admins
listed as true under /admins/{uid} can read enquiries or update their status.
Public write access is limited to creation at a generated child key. Public
reads are denied.

CONTACT FLOW
------------
The page sends the email notification, then saves the enquiry to Firebase.
If email notification fails but Firebase succeeds, the enquiry is still saved
and the user sees a success state with a notification warning.
If Firebase rejects the save, the user sees a specific permission/rules hint.
The page prevents repeated clicks while submitting.

IMAGE PERFORMANCE
-----------------
This project does not contain local raster image assets. Existing remote
Unsplash images remain remote; HTML images are lazy-loaded below the fold and
decoded asynchronously. Image URLs can only be fully self-hosted and converted
to local WebP/AVIF files after the original image assets are downloaded and
added to the project. Do not claim that remote images have been converted
inside this ZIP.
